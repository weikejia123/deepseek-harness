# session-orb（会话状态球）

一个 DSH 动态 Cordis 插件（**纯 Client 半区**）：在 Web 页面右上角显示一个可拖动的悬浮球，
一瞥即知 dsh 的**全局会话工作状态**——有多少会话正在运行、是否有会话完成但尚未查看、
是否有会话正等待你处理（审批 / 方案确认 / 提问）。

## 交互设计

设计目标：**一瞥即知、平静优先、仅在值得注意时升级提示**。参考通知徽标与工作负载指示器范式：

| 层 | 编码 | 含义 |
| --- | --- | --- |
| 球心数字 | 顶层会话总数 | 全局会话规模 |
| 外圈 conic 弧 | 运行中会话占比 | 当前工作量（忙碌程度） |
| 右上徽标 | 需要你注意的数量 | 最高优先级信号 |
| 球体颜色 | 蓝=空闲 / 暖橙呼吸=运行中 | 状态底色 |
| 红色描边 + 徽标脉冲 | 有完成未查看或等待交互 | 需要行动（脉冲仅在计数变化时重播一次，不持续骚扰） |

交互动作：

- **拖拽**移动悬浮球（指针捕获，位置保存在当前页面会话内）；
- **点击**展开面板：`需要你注意`（等待审批/方案确认/提问、完成待查看）→ `运行中` → `其他会话`（各段内保持时间倒序）；
- **会话行两行布局**：第一行 状态点 + 标题 + 状态标签；第二行 **归属项目**（蓝色）+ 相对时间（灰色）——多会话时一眼看出每个会话属于哪个项目；
- **点击某行**：`sessions.open(id)` 直接跳转到该会话并收起面板；
- **全部标为已读**：本地记认全部"完成未查看"（页面会话期内有效）；
- **悬停**：一行文字摘要，无需展开即可了解全局状态。

## 归属项目的解析（三级来源）

会话行第二行显示的"归属项目"按以下优先级解析：

1. **工作区权威账目**：遍历 `useWorkspaces` 的 `items`，用每个工作区的 `sessionIds`（工作区对会话的归属账目）反查会话 → 显示该工作区的 `title`（支持重命名）；
2. **路径匹配**：会话 `cwd` 与工作区 `path` 做精确匹配，再尝试最长前缀匹配（会话可能在工作区子目录）；
3. **目录名兜底**：取会话 `cwd` 的最后一段目录名。

若会话标题本身已是项目名（未命名会话的标题默认回退为项目目录名），则不重复显示项目行。

## 数据来源（为何纯客户端）

- `shell.overlay` 标准 props 的 `useSessions` 快照选择器 hook——会话列表与状态由运行时**实时推送**，
  插件订阅即得，不需要 Host RPC，也不需要轮询；
- 会话状态字段直接复用侧边栏语义：
  - `running` → 运行中；
  - `completed` → "完成但未选择未打开"（侧边栏绿色"完成"提醒）——正是"完成未查看"；
  - `pendingInteraction` → `approval`（等待审批）/ `plan-review`（等待方案确认）/ `question`（等待输入）；
- 顶层会话 = 无 `parentId` 且非 subagent 子项（子任务不重复计入徽标）；
- 当前正在查看的会话（`list.current`）不计入"需查看"，打开会话即自动记认。

## 安装 / 更新

动态插件只存在于当前 DSH 进程，源码以此目录为准。工作流：

1. 让 Agent 读取 `client.js` 内容；
2. Agent 调用 `cordis_define`：`idPrefix` 取 `manifest.json` 的 `idPrefix`（`sess`），`code.client` 使用本文件内容；
3. `cordis_run` 激活并在 Web UI 批准；
4. 页面右上角出现会话状态球。

## 已知边界

- "已读"记认与拖拽位置均为页面会话期内存态，刷新页面后重置（完成状态本身由 Host 维护，
  打开会话后 `completed` 自动清除）；
- 依赖 `shell.overlay` 槽位与 `useSessions`/`ctx.sessions`，若这些运行时面变化，插件需随版本适配。
