# 会话四种模式详解：标准 / PTC / 极简 / 创造

- **分析时间**：2026-08-15
- **项目版本**：`0.1.0-rc.5`（代码基点 upstream `47f943859b` + 本地 wkj-dev 分支）
- **分析方法**：全部结论基于源码直读，关键断言附文件路径与行号

dsh 的「会话模式」即 agent preset：每个会话创建时选定一套 agent 组合（工具集 + system prompt + 行为插件）。shipped 四个 preset 位于 `apps/cli/config/agent-presets/`：

| 目录 | 显示名（`preset.yml`） | order | 一句话定位 |
|---|---|---|---|
| `standard` | 标准模式 | 1 | 功能完整的编码 Agent：文件编辑、Shell、检索、Skills、计划、目标、子代理、工作流 |
| `code` | PTC 模式 | 2 | 标准模式全部能力 + 工具改以 Code Mode SDK 呈现，模型用一个 TypeScript 程序组合多步操作 |
| `minimal` | 极简模式 | 3 | 仅持久 bash + str_replace_editor 的双工具编码 Agent |
| `cordis` | 创造模式 | 4 | 标准模式全部能力 + 运行时检查、插件实验和 preset 创作指导，用于创建自定义 preset |

## 1. preset 机制基础：模式如何被发现、选定与切换

理解四种模式之前，先建立机制底座（实现包 `packages/preset/agent-presets`，其 README 是最完整的机制文档）。

### 发现与信任

- **preset = 一个含 `agent.cordis.yml` 的目录**，目录名即 id（须匹配 `^[a-z0-9][a-z0-9-]*$`，`src/preset.ts:18`）；`preset.yml` 只承载展示元数据（`name`/`description`/`order` 三个字段，除此之外没有别的字段，`src/metadata.ts`）。
- 发现 roots = CLI 注入的 shipped 目录（`apps/cli/src/profile-boot.ts:35` 指向 `config/agent-presets/`，以 `trust: 'system'` 注入）+ 用户目录 `$DSH_HOME/.agent-presets`（`trust: 'user'`，`src/discovery.ts:41`）。**用户自创模式就放这个目录，发现即生效**。发现无缓存，每次重读。
- roster 行由部署组合插入：`packages/bundle/web-app/cordis.patch.yml:420-424`，`default: standard`。

### 挂载模型：standing mount + scope 认父

- 每个 preset **每进程只挂载一次**，挂在 standing scope（key 为 `{ agentPreset: preset.id }`）下；每个会话的 agent 通过 `bindScopeParent` 把自己的 scope 认父到该 standing key，解析视图为 `agent → preset → global` 逐层遮蔽（`src/index.ts:286,514`）。standing mount 存活在所有 agent 之外，文件变更产生新一代、只影响后续会话。
- **isolate realm 纪律**：preset 内拥有服务的行必须放进带 `isolate` 的 group（如 `isolate: { planMode: true }`），否则两个 preset 的同名服务会在 root realm 冲突。挂载后审计会拒绝三类组合：无 scope 目标、未激活行、**泄漏到 root realm 的服务**（`src/mount.ts:189-203,333-367`），包不变量在每次服务通知时重查。

### 选定与切换

- **创建时**：RPC `sessions.create` 的 `agentPreset` 字段（`packages/host/apiproxy/src/api/sessions.ts:254-262`），省略时取用户 settings 的 `default`（缺省 `standard`）。选定后 id 写入 **session header 的 `agentPreset` 字段**（`packages/core/session/src/types.ts:98`）并持久化。
- **切换限制**：只能在**空会话**切换——事件流中尚无 `turn/start`（`api-proxy.ts:500-509`）；已开始的会话返回 `agent-preset-locked`。设计理由（本系列 05 篇场景 E 已述）：换工具集会让已落日志的 tool call 无法重演，这是刻意的不变量保护。切换成功追加 `agent-preset/selected` 事件（header 保持冻结，作为创建事实）。
- **resume 冲突**：恢复会话时指定的 preset 与记录不符则抛 `agent-preset-conflict`——已记录的 preset 永远赢。
- **子 agent 继承**：subagent 通过 `composeFrom` 认父到父方同一代 standing mount，绝不重新 mount（`packages/subagent/subagent/src/child-agent.ts:168`）。

## 3. PTC 模式（code）：工具呈现层的整体切换

PTC（Programmatic Tool Calling，仓库内称 Code Mode）是本系列最值得展开的模式。它的 diff 极小——**`code/agent.cordis.yml` 与 standard 逐字节相同，只多一行**（`:259-262`）：

```yaml
- id: tool-presentation
  name: '@deepseek-ai/dsh-agent-tool-presentation'
  config:
    mode: code
```

但这一行触发的是模型交互面的整体重构。

### 模型视角的变化

普通模式（`native`）下模型看到 N 个工具 schema，每次动作一次原生 tool call。PTC 模式下：

- **线上工具坍缩为一个 `run_code`**（保留名，`packages/core/tools/src/code-mode.ts:20`），参数为 `code`（一段 async TypeScript 函数体，仅可擦除语法，支持顶层 `await`/`return`）与 `description`（UI 标签）；
- 所有真实工具的签名以**生成的 TypeScript SDK 声明**进入 system prompt 的 `tools:sdk` section（`packages/core/tools/src/ts-types.ts:273` `renderToolsSdk()`）：`jsonSchemaToTs()`（`ts-types.ts:240`）把每个工具的 `parameters`/`output` JSON Schema 渲染成 TS 类型字面量，模型看到的是一份 `declare const tools: { ... }` 的完整类型化 API；
- 配套固定使用说明（`SDK_INSTRUCTIONS`，`ts-types.ts:250-259`）规定交互契约：`await tools.name(args)` 调用、失败抛 `ToolCallError`、`Promise.all` 可安全并行、**只有 `return`/`console.log` 的内容回到对话**——中间工具结果不进模型上下文，模型必须自行筛选（curate）返回值；
- 另有一段坍缩提示「`run_code` is the only tool you can call directly」（`CODE_ONLY_INSTRUCTION`，`packages/core/tools/src/index.ts:58`），且执行层强制：模型直呼任何非 `run_code` 的工具名会被解析为 `UNKNOWN_TOOL`（`collapses()`，`index.ts:1324-1326`）。

模式是三态的：`ToolPresentationMode = 'native' | 'code' | 'both'`（`index.ts:651`），`both` 同时给原生 schema 和 SDK。

### 执行链路

模型输出 `run_code({code, description})` 后的完整链路：

1. **执行位置是 worker thread**：`WorkerThreadCodeRuntime`（`packages/code-runtime/code-runtime-worker-thread/src/index.ts:238`）为每次 run 新建一个 Worker；程序先经 `stripTypeScriptTypes` 去类型（语法错误/non-erasable 语法直接失败、不 spawn worker），worker 侧用 `AsyncFunction` 构造器以 strict 模式执行（`bootstrap.ts:405-412`），注入 `tools` 命名空间、错误类和 5 方法 console shim；
2. **工具调用桥接回注册表**：程序里 `tools.xxx(args)` → worker 侧桥函数 postMessage `{type:'call',...}` → 宿主 `onCall`（按 own-property 查找 binding、防 `constructor`/`__proto__` 伪造）→ binding 把子调用送进注册表的分阶段调度器，**复刻原生 loop 的并发契约**：parallel 类调用最多重叠 `maxParallelSubCalls`（默认 10），exclusive 调用形成屏障，结果按提交顺序 commit。子调用带父 token，subCallId 形如 `CallId("${exec.callId}:code:${n}")`；
3. **权限不旁路**：子调用走注册表原生 pre/guard 管线，与普通工具调用同等受审批/权限约束——Code Mode 不是权限后门；
4. **结果回传**：程序结束后只有 `{logs, result}` 经 `output.render` 渲染进模型历史；失败转为结构化 isError（`CodeRunFailedError`，含失败 kind 与捕获日志），模型可自我修正。

### 日志与可回放性

「模型可见 ⟺ 已落日志」的不变量在 PTC 下拆成两层：外层只有 `run_code` 自己的 `tool/result` 进入模型历史；每次子派发记两条 log-only 事件 `tool/code-dispatch-start` 与 `tool/code-dispatch`（携带 rootCallId/parentCallId/subCallId/name/arguments/isError/content，声明合并在 `packages/core/tools/src/types.ts:25-57`），追加前过 `tools/code-dispatch-log` waterfall，spill 后端可把大内容替换为 preview+locator。回放与 UI 渲染因此能完整重建一次 `run_code` 内部的全部子调用。

### 约束与预算

模块注释明确定性「containment, not a security boundary: model code has bash-equivalent trust」（`code-runtime-worker-thread/src/index.ts:3-5`）。具体约束：每次 run 全新 worker（无跨 run 状态）、`env: {}`、`resourceLimits.maxOldGenerationSizeMb` 默认 512 MiB；三项预算全部是 schemastery Config（cordis.yml 可改）：`computeMs` 默认 60s（按 worker 自身 eventLoopUtilization 计量的**忙时**，等慢工具不计、热循环必计）、`maxWallMs` 默认 600s 墙钟兜底、`maxOutputBytes` 默认 64 MiB；abort 信号硬停（`worker.terminate()`，同步死循环也杀）。runtime 本身挂在宿主平面（`packages/bundle/web-app/cordis.patch.yml:47-49` 的 `code-runtime` 行），preset 行通过 `ctx.inject` 等待它，缺失则挂载即 fail loud。

### 价值定位

PTC 的收益是**把多步操作压缩成一次模型往返**：读 10 个文件、过滤、汇总，在 native 模式是 10 轮 tool call（每轮结果都进上下文），在 PTC 是一个程序——中间结果留在 worker 内存，只有 curate 后的结论进对话。省 token、省延迟、上下文更干净；代价是模型必须会写正确的 TS、且中间过程对模型自身也不可见（只能靠 console.log 自我观察）。schema→TS 的转换由 `dsh-tools` 自家的 `ts-types.ts` 完成，**与 typert 包无关**（typert 是 Host↔consumer 的 RPC 网关，常见误读）。

**文档**：`docs/subsystems/code-runtime.md`；Agent Notes `.agents/notes/implemented/feature/2026-06-15-code-mode.md`（奠基设计）、`2026-07-20-code-mode-typed-tool-returns.md`、`2026-07-31-code-mode-language-dispatch.md`（已有 Python 渲染器 `py-types.ts` 的伏笔）。

## 4. 极简模式（minimal）：最小可信组合

`minimal/agent.cordis.yml` 仅 62 行，与 standard 不是拷贝关系而是全新最小组合，只有三个顶层 entry：

1. **`persona`**：`text: You are a helpful software engineer assistant.` + `complete: true`（persona 即完整 system prompt，全局身份、Web orientation、工具指引等段落一律不再追加）+ `includeRuntimeContext: false`（抑制运行时上下文快照）——连 prompt 装配都极简化；
2. **`persistent-shell` group**（`isolate: { terminals: true }`）：`dsh-terminal` + `terminal-bash`（超时 300s）+ `dsh-tool-bash-persistent`——**持久 bash**，会话级的同一个 shell，cd/环境变量跨调用保留；
3. **`filesystem` group**（`isolate: { fs: true }`）：`fs-local` + `dsh-tool-str-replace-editor`（`maxOutputChars: 16000`）。

注意 `fs-local` 的精妙处：它是**裸本地 FS provider，用 entry-local realm 遮蔽宿主组合里 sandbox 化的 `ctx.fs`**——遮蔽只对本 preset 生效，宿主与其他 preset 不受影响。也就是说极简模式不仅工具少，还刻意绕开了 fs 沙箱策略，换取行为的完全可预期。

**没有的东西**同样重要：无 compaction、无 AGENTS.md 注入、无 plan mode、无 skills、无 web、无 todo、无 ask-user、无 goal、无 jobs、无 subagent/workflow。适用场景：评测基线、回归测试、教学演示——两个工具 + 一句 prompt，把「agent 循环本身的行为」从组合复杂度中剥离出来。

## 5. 创造模式（cordis）：agent 创造 agent

创造模式用于**创建自定义 preset 和运行时插件实验**。它与 standard 同样逐行相同，只有三处差异（`cordis/agent.cordis.yml`）：

1. **persona 扩写**（`:17-29`）：告知模型「你可以读写自己运行的 harness」、host/preset 两平面的归属规则、自创 preset 落盘位置 `$DSH_HOME/.agent-presets/<id>/`、**禁止修改 shipped 安装**、写作前先加载 `editing-cordis-compositions` skill；
2. **多挂 `tool-cordis`**（`:245-246`）：运行时自修改工具集；
3. **`skill-filesystem` 加 `customSkillDirs`**（`:255-259`）：注册 preset 自带的两个 skill——`editing-cordis-compositions`（组合文件编辑指导，154 行）与 `cordis-plugin-development`（动态插件开发指南，420 行），位于 `apps/cli/config/agent-presets/cordis/skills/`。

### tool-cordis：七个工具

`packages/extensions/tool-cordis/src/index.ts` 提供七个工具（注意文档漂移：preset 头注释和 skill 里仍写旧名 `cordis_mount`/`cordis_unmount`，当前实名是 define/run/stop/undefine）：

| 工具 | 作用 |
|---|---|
| `cordis_inspect_list` | 列出 Host + Client 全部 Inspect Provider 目录（用途、只读方法、输入/输出 schema） |
| `cordis_inspect_query` | 执行某 Provider 的只读查询：Host 侧可查服务方法签名（`Service.listService`）、事件目录（`Event.listEvents`）、沙箱可用符号（`Builtin.listBuiltins`）、当前 agent 实际可见的工具 schema（`Tool.listTools`）；Client 侧可查活 slot 树、主题 token 等。**不能调用业务服务、不能改运行时** |
| `cordis_inspect_self` | 查本会话动态插件自身：Plugin 摘要 → 版本指针（current/next）→ 某 immutable Package 的源码 + 运行时诊断（fiber 等待态、renderFailure、error/stack） |
| `cordis_define` | 登记一个不可变 Package（host/client 两半源码）：只校验参数 + 语法预检，**不执行、不请求审批** |
| `cordis_run` | 激活一个精确 Package：host-only 直接 `running`；带 client 半则先发审批卡（`awaiting-approval`），用户在 UI 批准后浏览器异步完成 |
| `cordis_stop` | 停当前 Run、取消未完成审批，保留全部 Package 与授权（幂等） |
| `cordis_undefine` | 永久删除：停 + 删全部 Package/授权/版本指针 |

版本模型：`currentPackageId`（最近完全成功）/ `nextPackageId`（待审批或最近失败目标）/ `pluginRunId`（单次激活尝试）；update 失败不自动回滚，需显式 run current 版本。另有 `agent/pre-step` 监听：用户消息里的 `@<pluginId>` 自动注入该插件的身份与版本上下文（`index.ts:381-398`）。

### 动态插件的执行环境

- **Host 半（node:vm 沙箱，`cordis-host-runner/src/sandbox.ts`）**：代码作为 async 函数体在新 realm 里 `runInContext` 求值；可见面只有带标签的 console、`harness`（defineTool/registerTool/handle）与编码工具函数；`require`/`fetch`/`setTimeout` 等换成抛「改用 cordis 服务」的教学错误 trap，`process`/`Buffer` 为 `undefined`；`vmTimeoutMs` 默认 5s 只约束同步求值段。插件 `apply` 拿到的是 **Proxy 白名单 façade**（`guard.ts:718-781`）：只能触达 `effect/on/once/provide` 和 inject 声明过的服务，框架内部（root/fiber/registry…）一律拒绝，`ctx.tools.get` 只返回 schema 视图（防止绕过工具策略链），跨 realm 数据经 `cloneJson` 物化。
- **Client 半（闭包求值，`cordis-client-runner/src/client/evaluator.ts`）**：`new Function('React','console','styles','host', …traps, body)`——参数名即符号面，UI 必须 `React.createElement`（无 JSX/import），`styles.insert(css)` 的样式随卸载自动清除，`host.call` 走 package 私有 JSON RPC 回 host 半。
- **生命周期**：define（入进程注册表）→ run（host 半建 fiber → client 半审批 → 闭包求值 → 落定 currentPackageId）→ stop（fiber.dispose，一切注册都是 effect，回收干净）→ undefine。**只活在进程内存，重启即失**；持久化形态是把成果写成用户 preset 目录。

### preset 创作指导的三载体

「指导 agent 创造 preset」不是靠一个超长 prompt，而是三层协同：persona 段（规则与红线）→ `editing-cordis-compositions` skill（方法论：平面判定——工具/persona/prompt 段归 preset，registry/持久化/沙箱审批/模型路由归 host；创作流程 `copy(from,id)` → 改元数据 → 逐行改组合 → `standingKeyFor(id)` 做真实 mount 校验，能抓出包解析失败/配置非法/未激活行/服务泄进 root realm 四类错误）→ roster 服务 `ctx.agentPresets`（`list/read/copy/resolve/standingKeyFor`，即机制底座本身暴露给 agent 用）。产出落到 `$DSH_HOME/.agent-presets/<id>/` 后，下次会话创建即可选用。

### 安全边界：防君子不防小人

官方定性高度一致：「**The sandbox is containment for honest code, not a security boundary**——load this plugin as deliberately as you would grant a bash tool」（`tool-cordis/README.md:102`）；preset 头注释更直白：「**Treat a session on this preset as shell access**」（`agent.cordis.yml:9-12`）。声明了 `fs`/`bash` 等 inject 的动态代码拿到的是真实服务实例，host-realm helper 闭包是逃逸通道，vmTimeout 管不住 async 死循环。防护的本质是**可处置性**（stop 即卸载）+ **教学式护栏**（trap 重定向、façade 白名单）+ **审批闸**（client 半首次运行必须用户批准；host-only 半无审批）。演示入口：`pnpm run demo:cordis`（`scripts/demo-cordis.mjs`，web 模式起在 3081 端口）。

## 6. 四模式对比与选型

| 维度 | 标准 | PTC | 极简 | 创造 |
|---|---|---|---|---|
| 组合方式 | 基线 | = 标准 + 1 行呈现切换 | 独立最小组合（62 行） | = 标准 + persona/skills/tool-cordis |
| 模型可见工具 | 全部 schema | 一个 `run_code` + TS SDK | `bash` + `str_replace_editor` | 全部 schema + cordis_* |
| system prompt | 完整装配 | 完整装配 + SDK section | 一句 persona（`complete: true`） | 完整装配 + 创作规则 |
| fs 沙箱 | 宿主策略 | 宿主策略 | **裸 fs-local 遮蔽** | 宿主策略 |
| 信任级别 | 常规 | 常规（子调用走原生审批） | 常规 | **视同 shell 访问** |
| 典型用途 | 日常编码 | 多步批处理、省 token | 评测基线、教学 | 造自己的 preset/插件 |

一句话选型：日常用标准；批量多步操作让模型少跑几轮用 PTC；要最干净的基线行为用极简；想让 agent 帮你造新的模式/插件用创造——造出来的 preset 写进 `$DSH_HOME/.agent-presets/`，本身又成为可选的第五种模式。

## 7. 标准模式关键组件深挖

标准模式组合表里的几行 entry 本身值得单独展开：它们各自是一个完整子系统。本节逐项给出机制解析（实现包均在 `packages/` 下，结论附路径与行号）。

### 7.1 agent-instructions：项目指令文件的发现与注入

`packages/context/agent-instructions` 负责把 AGENTS.md 类文件注入对话，回答「包含哪些文件、检索哪些目录、如何注入」三个问题：

**包含哪些文件**（`src/config.ts:11-13`）：

- 项目文件候选：默认 `['AGENTS.md', 'CLAUDE.md']`，Config `instructionFileCandidates` 可整体替换；
- 本地覆盖候选：默认 `['AGENTS.local.md', 'CLAUDE.local.md']`，同目录内排在 base 文件之后，`localInstructionFileCandidates: []` 可禁用；
- 用户全局文件：**硬编码为 `$DSH_HOME/AGENTS.md`**（`src/render.ts:98`，不可自定义）。

**检索哪些目录**（`src/files.ts`）：

- 起点是会话 cwd；`findProjectRoot` 从 cwd 向上找第一个含 `projectRootMarkers`（默认 `['.git']`）的目录作为 project root，一路找到文件系统根都没有 marker 则回退用 cwd 本身；
- 收集范围 = **project root → cwd 的祖先链**，顺序从最宽泛到最具体；不越过 project root 向上，baseline 也不递归子目录；
- 例外：运行期间 `read`/`write`/`edit` 工具触碰文件后，会补收集 cwd → 被触文件目录之间的后代链上的嵌套 AGENTS.md（`index.ts:70-78`）——「读到哪个子目录，哪个子目录的规矩就进场」；
- 去重：绝对路径去重 + **同目录按 trim 后内容的 SHA-1 去重**——所以 `CLAUDE.md` 软链 `AGENTS.md` 只渲染一份；不同目录即使内容相同也不合并。

**如何注入**：不是写进 system prompt，而是注入一条 **user 角色消息**，内容包在 `<system-reminder>` 帧里（`render.ts:10-11,242`）。时机是 `agent/pre-step`——**每个 step 前**重新 compose 并插入到已声明消息批次之后（`index.ts:322-348`）；文件变化感知是工具驱动的（监听 `tools/result`），没有文件系统 watcher；per-session 版本缓存避免重复读盘。落日志为普通 `user/message` 事件（`source.kind === 'agent-instructions'`），增量更新带 `changes: [{action: 'set'|'replace'|'remove', path, digest}]`，回放可完整重建。

**预算与截断**：`maxBytes` 必填（base bundle 配 65536，`packages/bundle/base/cordis.patch.yml:232-235`），`maxSourceBytes` 默认 1 MiB（单文件超限整文件忽略）。整体超预算时从**最宽泛的文件开始整体丢弃**、保更具体的；只剩一个仍超则二分截断（UTF-8 安全）；被丢弃/截断都在文本头部写 marker，模型知道自己看到的是残本。

### 7.2 plan-mode：计划模式的定义与特性

`packages/plan/plan-mode` 的定义出人意料地小：**plan mode 是一个落日志的、逐 agent 的布尔协作状态，本质是软指引**——激活时不禁任何工具、不改权限，只是每次模型请求多渲染一段部署方配置的 prompt section，外加一个出口工具（`src/index.ts:1-7`；README 明示 sandbox/approval 轴独立配置，不读写 plan 状态）。

- **进入/退出**：用户命令 `/plan [message]` 进入（带消息则选中后 steer 为普通用户消息）；退出两条路——`/plan off`，或模型调用 `exit_plan_mode`。没有 `EnterPlanMode` 工具。
- **状态提交语义**：空闲时立即 `session.append('plan/mode', { active })`；turn 运行中则挂起为 pending intent，等下一个被接受的 `pre-step` 边界提交（`src/index.ts:205-222,425-445`）——切换永远落在事件流的安全边界上。
- **为什么不改工具目录**：`exit_plan_mode` 始终注册，请求 shape 保持稳定（KV cache 复用）；约束全靠 prompt——standard preset 的 section 文本（`agent.cordis.yml:113-124`）写明「只做非变更性读取/搜索/静态分析」「工具目录不变是刻意的，本规则覆盖工具描述里的变更引导」「计划要决策完备（目标、成功标准、按子系统分组、边界情况、测试、验收）」「`exit_plan_mode` 必须是该响应里唯一且最后的工具调用」。
- **产出物与审批**：计划不写文件，作为 `exit_plan_mode` 的必填 `plan` 参数（非空 markdown、以 `#` 标题开头）经标准 `tool/call`/`tool/result` 事件落日志。调用触发 `plan-review` 用户问题（Approve / Keep planning）：Approve → 返回 `{ approved: true }` 并静默挂起退出；Keep planning 或自定义反馈 → 以错误形式把反馈回给模型重新修改；评审被解散 → 留在 plan mode 等待。
- **状态与隔离**：`plan/mode` 是 log-only 事件，fold 得出当前值，resume/fork/compaction 直接从日志恢复（无需 live mirror）。放 isolate realm 的原因写在 preset 注释里：「Plan state is per-agent by nature — entry-local realm 不是变通，而是正确的生命周期」（`agent.cordis.yml:102-103`）。
- **Config**：只有 `section` 一个字段（必填非空），未知 key 加载即抛错——显式拒绝塞进工具过滤、审批策略等配置。

### 7.3 会话压缩（compaction）：阈值、摘要与事务

四个包分工：`compaction`（Service Definition，`ctx.compaction`）、`compaction-basic`（唯一 provider，`inject = ['llm', 'tokenMeter', 'sessions']`）、`command-compact`（`/compact` 命令）、`compaction-tool-result-pruner`（独立服务 `ctx.toolResultPruner`）。preset 注释里有一个容易忽略的设计：`tokenMeter` 刻意留在 host 平面**不进 realm**（它服务所有 session），而 pruner 必须与 compaction-basic 同 realm（后者经 `ctx.get('toolResultPruner')` 读它）。

**触发**（`compaction-basic/src/index.ts`）：

- **自动·压力路径**：每个 step 前 `tokenMeter.measure(session)` 计量，与 `floor(contextWindow × thresholdRatio)`（默认 0.8）比较；超阈值先跑一遍 model-free 剪枝再重测，仍超才进入摘要压缩（默认最多 2 轮）；contextWindow 由 LLM adapter 的 `resolveModelInfo` 提供，缺失即抛错。token 计量优先用最近一次 assistant 消息携带的真实 `usage`，否则启发式估计（`packages/llm/token-meter/src/index.ts:232-259`）。
- **自动·溢出路径**：请求报 `CONTEXT_WINDOW_EXCEEDED` 时绕过阈值与保留策略直接强制压缩一次，返回 `{ kind: 'retry' }` 让 agent-loop 重试（每 agent 上限 `maxOverflowRetries` 默认 1 次）。
- **手动**：`/compact` → `compactNow`，经 `agent.runMaintenance` 在 agent idle 的 maintenance 相位串行执行（忙碌则报 `busy`），`retainTokens = 0`（低于自动阈值也尽量压）；成功后强制 `sessions.flush()` 保证恢复点完整。

**压缩做什么**：调模型做摘要。摘要 prompt（`summarizer.ts:31-66`）要求固定 Markdown 结构（意图 / 技术概念 / 文件与代码 / 错误与修复 / 待办 / 当前工作 / 下一步 / 关键上下文），且为复用 KV cache，请求原样带上会话自己的 system prompt、tools 与消息前缀，instruction 是唯一新增内容。选区从头部压起、尾部逐字保留 `retainRatio`（默认 0.16 × contextWindow），边界用 tool-pairing 平衡算法保证不切开 tool-call 与 tool/result 配对；摘要落地前强制校验「摘要必须更小」。

**事务语义**（`region.ts:137-151` 的 JSDoc 即契约）：

- `compaction/start` 事件本身就是 durable 锁——摘要让出执行权之前锁已落盘，并发第二事务被拒绝；
- 每个事务恰好一次 `compaction/end` 尝试，失败的 end 带 `error`；**没有「撤销已写事件」的回滚，也不需要**——被遮蔽的旧事件从未被改写，失败天然安全；
- 提交阶段不让出执行权：`compaction/summary`（log-only，含 shadowedRange、provider/model、usage、rawOutput）+ 一条带 `surfaceOp: { op: 'replace', start, end }` 和 `sourceEventSeqs` 的新 `user/message`（内容 = 检查点前导文 + `<compacted-summary>` 帧）同步连续落盘，随后 `compaction/end`；
- 摘要期间允许并发注入但提交前复核稳定性：手动事务校验被选 span 不变，自动事务对整个 surface 逐节点深比较，变了报 `changed`；
- fork/resume 交互：若未匹配的 start 之后存在更新的 `session/end-seed`，认定锁属于上一会话生命周期、不再拒绝新压缩——进程在压缩中途死亡不会永久锁死会话。

**tool-result-pruner 的角色**：压缩前的「第一遍廉价减重」——不调 LLM、不选区间，单个 tool result 文本超 `thresholdChars`（默认 8192 码点）就保头 4096、尾 1024、中段替换为固定 marker（Unicode code point 安全切分）。它只被 compaction-basic 在压力/溢出路径上调用，自己不注册任何监听；每次剪枝同样以 `compaction/prune` 计量事件 + replace 事件对落日志。

**Config 一览**（`compaction-basic`，未知 key 加载即报错）：`thresholdRatio`（0.8）、`retainRatio`（0.16，须 < thresholdRatio）、`retainTokens`（绝对值，与 ratio 互斥）、`summarizationProvider/Model`（成对设置，缺省走最近路由）、`maxTokens`（8192，摘要截断即失败）、`compactionRetries`（1）、`maxOverflowRetries`（1）、`modelPolicies`（按精确 provider/model 覆盖全部策略）、`auto`（true）。

### 7.4 网络搜索：DeepSeek 原生支持与配置

**结论：DeepSeek 模型的原生网络搜索是支持的，且是默认发货配置。** 实现不是 chat-completions 的某个开关，而是调用 DeepSeek 官方的 **Anthropic 兼容端点** `https://api.deepseek.com/anthropic/v1/messages`，请求体携带服务端工具 `web_search_20250305`（`packages/web/web-search-deepseek/src/provider.ts:205-213`）——搜索在 DeepSeek 服务端完成，每次搜索是一次辅助模型调用（默认模型 `deepseek-v4-flash`，`maxUses` 默认 5）。注意它**不复用** `DEEPSEEK_BASE_URL`（端点路径不同，provider.ts:29-35），但**与聊天共用同一个 `DEEPSEEK_API_KEY`**。

**默认组合已挂好，开箱即用**（`packages/bundle/base/cordis.patch.yml:404-418`）：

```yaml
- id: web
  name: '@deepseek-ai/dsh-web'
  config: { searchProvider: deepseek-official }
- id: web-search-deepseek
  name: '@deepseek-ai/dsh-web-search-deepseek'
  config: { apiKeyEnv: DEEPSEEK_API_KEY }
- id: tool-web
  name: '@deepseek-ai/dsh-tool-web'
  config: { fetch: false, searchTimeoutMs: 60000 }
```

即：只要有 `DEEPSEEK_API_KEY`，模型在标准/PTC/创造模式里就有 `web_search` 工具可用。能力接缝是标准三分：`web`（Definition）+ `web-search-*`（Provider）+ `tool-web`（Consumer）；preset 只挂模型可见的 tool-web，`web` 服务与 provider 留在 host composition（`standard/agent.cordis.yml:245-246` 注释）。

**`web_fetch` 为什么默认关**：base bundle 注释明言——「Fetch stays disabled: that provider defers SSRF protection and the model would choose the request target」（`cordis.patch.yml:396-403`），本地 fetch 后端不阻止内网地址（`docs/subsystems/web.md:132`）。开启方法：patch 里把 `tool-web` 的 `fetch` 改为 `true` 并 insert `web-fetch-http` provider（现成示例 `examples/acp-agent/web.cordis.yml:11-21`）；fetch provider 自带 URL 长 2048 / 响应 5MB / 正文 10 万字符 / 30s 超时 / 最多 5 次同源重定向的限制。

**换搜索引擎**：三个 provider 注册进同一注册表——`deepseek-official`（DeepSeek 原生）、`exa`（需 `EXA_API_KEY`）、`perplexity`（sonar 模型，返回生成答案而非裸结果，需 `PERPLEXITY_API_KEY`）。选择规则（`packages/web/web/src/index.ts:62-73,172-194`）：`ctx.web` 的 `searchProvider` 配置或 `$DSH_WEB_SEARCH_PROVIDER` 环境变量指定 id；未配置且恰好一个可用则自动选中；多个可用报 `WEB_PROVIDER_AMBIGUOUS`（不会先到先得）。

**可观测性**：每次搜索的 secret-free 请求体记入会话日志事件 `web/deepseek-search-llm-request`（provider.ts:80-85），满足「模型可见 ⟺ 已落日志」。请求同时发 `x-api-key` 与 `Authorization: Bearer` 双头兼容代理，redirect 一律报错（凭证防泄漏纪律）。

> 如实说明：源码按 DeepSeek 官方 Anthropic 兼容端点实现（`web_search_20250305` 工具类型、`deepseek-v4-flash` 默认模型），该端点与模型名以 DeepSeek 官方文档为最终依据。
